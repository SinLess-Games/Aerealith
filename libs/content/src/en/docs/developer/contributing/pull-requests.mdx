# Pull Requests

A pull request should explain the problem, solution, boundaries, verification, and operational impact.

Include:

- a concise outcome-focused summary
- linked issue or decision context
- user-visible changes
- tests and commands run
- screenshots for meaningful UI changes
- migrations, configuration, and rollout notes
- security and privacy impact
- known limitations

Keep unrelated refactors separate. Respond to review with code or evidence, and resolve discussions only when the underlying concern is addressed.
