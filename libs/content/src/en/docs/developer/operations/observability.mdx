# Observability

Observability should answer what failed, where, for whom, and since when.

Use structured logs, correlation identifiers, service and environment labels, latency and error metrics, and traces across important boundaries. Never log secrets, raw credentials, unnecessary payloads, or unrelated personal data.

Alerts should represent actionable user or service impact with an owner and response path. Dashboards support investigation but do not replace alerts.

Preserve enough context to distinguish code regressions, bad configuration, dependency failures, capacity limits, and abuse.
