# Operations

Operational guides must distinguish configured infrastructure from running consumers. Start with [Events & Queues](/documentation/developer/operations/events-and-queues), [Feature Flags](/documentation/developer/operations/feature-flags), and [CI & Delivery Checks](/documentation/developer/operations/ci), then review [Deployment](/documentation/developer/operations/deployment).

Operational readiness includes a repeatable deployment, meaningful health signals, protected diagnostics, ownership, and recovery procedures.

Before production exposure, define expected traffic, dependencies, limits, alerts, rollback behavior, and incident ownership. Changes should be observable enough to distinguish application, dependency, configuration, and platform failures.

Continue with [Deployment](/documentation/developer/operations/deployment), [Observability](/documentation/developer/operations/observability), and [Service Health](/documentation/developer/operations/service-health).
