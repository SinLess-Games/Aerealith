# Developer Documentation

This section explains how to understand, change, test, secure, and operate Aerealith. It distinguishes implemented behavior from proposals and historical research.

## Recommended path

1. Prepare the workspace with [Getting Started](/documentation/developer/getting-started) and [Local Development](/documentation/developer/getting-started/local-development).
2. Understand boundaries in [Architecture](/documentation/developer/architecture).
3. Review public contracts in [API](/documentation/developer/api).
4. Apply [Testing](/documentation/developer/testing), [Feature Flags](/documentation/developer/operations/feature-flags), and [Security](/documentation/developer/security) guidance.
5. Follow [Contributing](/documentation/developer/contributing) before opening a pull request.

## Documentation types

Architecture documents current structure. Designs and proposals describe possible changes. Decisions preserve accepted reasoning. Research records evidence. Operations and releases cover the production lifecycle. Reference pages provide stable lookup material.

</Requirement>
