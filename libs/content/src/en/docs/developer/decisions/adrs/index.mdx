# Architecture Decision Records

An ADR contains title, status, context, decision, alternatives, consequences, date, and owners.

Create one when a choice changes package direction, runtime topology, data ownership, public contracts, or a cross-project architectural constraint.

Statuses may include Proposed, Accepted, Rejected, Deprecated, and Superseded. Link the superseding ADR without erasing the earlier record.

Keep implementation progress outside the decision itself unless it changes the decision.
