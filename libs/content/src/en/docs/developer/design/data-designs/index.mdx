# Data Designs

Data design defines meaning and lifecycle, not only storage shape.

Document ownership, identifiers, invariants, relationships, access patterns, validation, tenant boundaries, sensitive fields, retention, deletion, backup, and recovery.

For schema changes, describe forward and backward compatibility, migration phases, backfill, verification, rollback, and how mixed application versions behave.

Collect the minimum data necessary and ensure logs and analytics do not create an unintended secondary store.
