# Design

Design documents make constraints, alternatives, interfaces, risks, and verification plans reviewable before implementation cost grows.

A design should state the problem, goals, non-goals, current state, proposal, data and security impact, operational behavior, alternatives, rollout, rollback, testing, and unresolved questions.

Use [Technical Designs](/documentation/developer/design/technical-designs), [Data Designs](/documentation/developer/design/data-designs), and [Security Design Reviews](/documentation/developer/design/security-design-reviews). Accepted durable choices should produce a decision record.
