# API

API documentation is contract documentation. Examples must match implemented routes, schemas, authorization behavior, and errors. Internal endpoints remain implementation details until explicitly published.

## Contract checklist

Every endpoint should define method, path, authentication, authorization, request schema, success response, stable errors, idempotency, retry behavior, and applicable limits.

- [Conventions](/documentation/developer/api/conventions)

- [Errors](/documentation/developer/api/errors)

Validate examples through tests or generated contracts when possible. Never document a proposed endpoint as available.
