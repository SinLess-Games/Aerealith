# User Documentation

Welcome to the Aerealith user guide. These pages explain how to begin using the platform, how to work with its available features, and where to find the research behind important product and engineering decisions.

<Requirement title="Active development">
  Aerealith is under active development. The features available to you may
  depend on your account, deployment, and enabled integrations.
</Requirement>

## Choose a path

## What you can expect

The user documentation is organized around tasks rather than internal implementation details. Each guide aims to explain:

- what a feature or workflow is for
- what you need before starting
- how to complete the task
- what information requires careful review
- where to go when something does not work

Developer-focused architecture, API, and contribution material belongs in the [Developer Documentation](/documentation/developer).

## Using Aerealith responsibly

Aerealith can help organize information, develop plans, summarize material, and support technical work. Generated output can still be incomplete, outdated, or incorrect.

Before acting on important output:

1. Verify factual claims against reliable sources.
2. Review generated code, commands, and configuration.
3. Do not enter secrets unless the workflow explicitly supports them.
4. Use qualified professional review for legal, medical, financial, safety-critical, or regulated decisions.
5. Keep a human decision-maker responsible for final approval.

## Finding information

Use the nested navigation to browse by topic. Folder arrows expand or collapse related pages, and the active branch opens automatically when you navigate to a document.

If a page is missing or unclear, report the affected page, the result you expected, and what happened instead. Specific examples make documentation issues much easier to reproduce and correct.
